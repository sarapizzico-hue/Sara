# Formatos de deck

Escolha **um**. Não misture arco G6 de 18 slides com combo Isoluz no mesmo arquivo.

## A. Combo curto (7–10 slides) — padrão atual para mix de produtos

Âncoras: `proposta-dental-muller.html` (7) · `proposta-isoluz.html` (capa, contexto, 1 slide/produto, âncora, investimento)

| # | Slide | Função | Ato |
|---|---|---|---|
| 1 | **Capa** | Tese Do X ao Y · Cliente × V4 · badge dos produtos | Narrativa |
| 2 | **Diagnóstico** | Reframe + evidências da EE/conta. Sem número de mercado | Narrativa + dados |
| 3…n | **Um slide por produto** | Nome de catálogo · pontual ou recorrente · o que instala neste cliente | Produto |
| n+1 | **Ciclo / o que muda** | Ordem certa (ex.: comercial pronto → demanda). O que muda na operação | Produto |
| n+2 | **Investimento** | Condição · o que está incluso · EE a favor se houver · um fecho | Decisão |

Dental Muller (referência viva no `main`):

1. Capa — Da origem relacional ao canal previsível
2. Diagnóstico estratégico — leitura da EE
3. EQV — comercial preparado para a demanda nova
4. Assessoria de Growth — demanda no ritmo do comercial
5. Sequência — comercial pronto; depois demanda
6. O que muda na operação
7. Investimento — dois produtos, um ciclo

Use este formato quando o brief tem **mais de um produto** e a sala não precisa ver fase a fase.

`data-act`: Capa+Diagnóstico → `narrativa` (Diagnóstico também carrega dados) · cada produto + ciclo → `produto` · Investimento → `decisao`. Nav de atos: Dados salta para o Diagnóstico. Divisor entre atos só se o brief pedir — 7 slides já respiram com a pílula.

## B. EC profunda (13–18 slides) — instalação comercial

Âncoras: `ESTRUTURA-ENTREGA-G6.md` · `g6/` · `g6-modelo/` (13) · `proposta-g6-estruturacao-comercial.html` (18)

Ordem na sala: narrativa (capa/contexto) → dados (vazamento + dores) → narrativa de solução (visão/promessa) → produto → recap → investimento.

### Mapa 18 slides (G6 entrega)

| Slide | Função na sala | Pergunta |
|---|---|---|
| 01 Capa | Tese em uma linha. Estado atual → estado instalado | O que esta reunião decide? |
| 02 Contexto | Reframe: não é o sintoma óbvio | Vocês não têm X. Têm Y. |
| 03 Vazamento | A conta na mesa. Entrada vs. o que escapa | Quanto a operação está vazando? |
| 04 Dores × produto | 4–6 dores nomeadas. Cada uma é o que o produto fecha | Onde perde previsibilidade? |
| 05 Visão | A ordem certa. Três passos + quote | Por que não apertar meta agora? |
| 06 Promessa | O que a V4 instala neste projeto | O que fica rodando no final? |
| 07 Formato | Tempo, carga, quem executa, ritmo, presencial, saída | Assessoria solta ou instalação? |
| 08 Escopo | Fundação operacional + controle/adesão | O que o time leva para o dia a dia? |
| 09 Fases | Trilho completo. Uma linha por fase, com horas | Qual a sequência até handover? |
| 10–15 Detalhe de fase | Entregas + “encaixe [cliente]” | O que sai desta fase — neste cliente? |
| 16 Pronto | Critérios observáveis (ex. título Receita Previsível) | Como sabemos que instalou? |
| 17 Recap | Dores de um lado, dados do outro. Antes do preço | O que está em jogo? |
| 18 Investimento | Âncora → condição única. Por que agora | Quanto — e por que fechar agora? |

### Variante 13 slides (`g6-modelo`)

Capa → Dor → Vazando → Sangria → Dores×cliente → CRM/controle → Visão → Produto → Fases → Sucesso → Personalização → Recap → Investimento

Use quando a sala não aguenta um detalhe por fase, mas a oferta ainda é **instalação** (não retainer de mídia).

Divisores (subcapa de ato) **antes** de Dados, Produto e Decisão. Trilho no divisor de Produto = nomes das fases desta conta. Spec do divisor: `dinamica.md`.

## C. 14 slides STEP (esqueleto Colli)

Capa → Tese → Contexto → Travas → STEP (Saber / Ter / Executar / Potencializar) → Case interno → Solução core → Essencial → Ondas → Papéis → Projeção → Investimento → Pedidos da semana → Próximos passos

Referências de conteúdo (não de visual Sora):

- Handover G6 — tese (“o problema não é X”), KPIs reais, pedidos da semana
- Farmácia Preço Popular — STEP e ordem antes de acelerar
- Hanaro × Jinro — papéis (V4 conduz, cliente executa, limite de escopo)

Slides vazios somem. Gate da sala fica só no briefing interno / script.

Este formato cabe quando a Sara quer o **wizard completo** (prova + papéis + pedidos). Se o brief não pede STEP/papéis, prefira A ou B.

## Script de pitch — blocos (não são slides do cliente)

Espelhar o arco do deck, em conversa:

1. Abertura leve + pergunta aberta (não preço, não “última semana”)
2. Reframe + evidências — o cliente fala
3. Conta / vazamento — confirma o número
4. Produto / time / escopo — **matar objeção de escopo aqui**
5. Alinhamento / gate — “o que te faz precisar pensar: valor, timing ou escopo?”
6. Um preço. Respira. Pede a venda + próximo passo

Não plante dúvida que o cliente não trouxe. Não use “sua meta é a minha”.

## O que não é formato de proposta

- Hub Farmer, pipe, score, plano de ação — ferramenta Sara
- Observação de contrato (`OBSERVACAO-CONTRATO-ENTREGAVEIS-G6.md`) — anexo jurídico, não deck
- PDF/PPTX/Word — export do HTML, ciclo separado
