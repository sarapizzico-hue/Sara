# Brief — preencher junto com a Sara

Sem brief completo, **não começa** proposta. Mudança de visual, escopo ou preço no meio do caminho só com brief atualizado — não por “ajuste rápido”.

Use esta ficha no chat. Preencha o que a Sara trouxer; marque `[FALTA]` no resto e espere.

## 1. Obrigatório (5)

```
Cliente:
Produto(s) do catálogo:          # EC · EQV · Growth · CRM · Social · SDR IA · E-com B2B
Preços finais:                   # âncora → condição  |  ou A/B se ela pedir
Referência visual:               # arquivo HTML âncora (não “igual à G6”)
Tese em 1 linha:                 # Do [jeito atual] ao [estado instalado]
```

## 2. Narrativa

```
Lede da capa:                    # o que instala, em quanto tempo, para quem opera
Reframe:                         # Vocês não têm problema de [sintoma]. Têm [causa raiz].
4 evidências desta conta:        # título — fato (não genérico)
Leitura:                         # palavra-número + frase
Quote da visão:                  # frase que o decisor possa repetir
Promessa:                        # o que a V4 instala neste projeto (não o catálogo)
```

## 3. Dados

```
Entrada (o que já funciona):     # volume, CPL, tempo de resposta, time
Vazamento:                       # número grande + o que é
Série mensal (se existir):       # jan:x, fev:y
Fonte de cada número:            # CRM, Meta, call do dia X, citado pela operação
Pergunta que o CRM não responde:
4 a 6 dores que o produto fecha: # cada dor precisa de dono no produto (fase ou entrega)
```

Regras:

- Número sem fonte não entra.
- Não prometa taxa de case maduro como se fosse desta conta.
- Se o ticket é baixo, use LTV / vazamento acumulado — senão a conta parece menor que o preço.
- Seis dores, não quinze.

## 4. Produto

```
Duração / carga V4:
Quem executa:                    # V4 + time do cliente (nunca “a V4 faz sozinha” sem brief)
Ritmo:                           # semanal, sponsor, checkpoints
Presencial:                      # onde a adesão se decide na sala
Saída:                           # handover + plano de continuidade
Fundação (o que instala):
Controle e adesão:
Fases ou ciclo:                  # nome · horas — o que faz — encaixe NESTE cliente
Critérios de “pronto”:           # o que o sponsor vê funcionando
Fora de escopo (se relevante):
```

Sem a linha **“Encaixe [cliente]”**, a fase é catálogo.

## 5. Decisão

```
Âncora (valor de referência):
Condição única (um preço):
Forma de pagamento:              # só se brief trouxer; senão omitir ou “conforme faturamento V4”
Por que agora:                   # uma frase com o dado que dói
Próximo passo:                   # assinatura / acessos / kickoff / data
```

Um preço. Desconto já embutido. Nunca escrever “desconto” no slide — é **condição comercial**.

## Prompt curto para colar no agente

```
Use a skill estrutura-proposta.

Cliente: [NOME]
Produtos: [CATÁLOGO]
Preços: [ÂNCORA → CONDIÇÃO]
Visual: [arquivo HTML]
Tese: Do [X] ao [Y].

Reframe: Vocês não têm [sintoma]. Têm [causa].
Dados (com fonte): …
Dores (4–6): …
Formato: [prazo / carga / quem executa]
Pronto: …
Por que agora: …

Crie proposta-*.html + script-*-pitch.html na raiz.
Não invente preço nem visual. Altere só o que este brief pede.
```

## Anti-retrabalho

- “Igual à G6” sem versão = ambíguo → pedir qual arquivo.
- Tipografia/layout depois do 1º draft = fora, salvo erro.
- Word/PDF depois do HTML = ciclo separado.
- Pipe/safra só mudam com dados novos — não no fluxo de proposta.
